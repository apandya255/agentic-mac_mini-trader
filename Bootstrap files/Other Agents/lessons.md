# Process Lessons — desk/lessons.md

One lesson per closed position, written at close, appended by the PM seat. This file is how the desk gets better — and it is about PROCESS, never outcome. "The trade lost" is not a lesson; "the flip-condition was too vague to check daily" is. "The trade won" teaches nothing; "the add at +2% was debated in one round when it deserved two" does.

Rules:
- One entry per close, ≤3 lines: what the process got right or wrong, and the specific change (if any) it implies — to a mandate, a checklist, a threshold.
- A lesson that implies a rule change does NOT change the rule — it gets flagged to the principal; rules change only on his word (SOUL.md).
- Monthly review (with MEMORY.md consolidation): patterns across lessons get consolidated; three lessons saying the same thing = a proposal to the principal.
- No self-flagellation, no victory laps. The verdict speaks (SOUL.md).

## Format
`[YYYY-MM-DD] #position (instrument, P&L, days held) — lesson. → implies: [nothing / proposal to principal]`
