## 2. Architecture Decisions

1. **Single-file generation preserved** — `dashboard.py` continues to produce one self-contained `dashboard.html` with all CSS, JS, and fallback data embedded. No build tools, bundlers, or external CDN dependencies were introduced.

2. **No framework adoption** — The implementation stays with vanilla JavaScript. Complexity is managed through well-named `render*()` functions that return HTML strings, not through a component library.

3. **No charting library** — Equity chart and sparklines remain pure inline SVG generated by JavaScript. This keeps the file self-contained and avoids version-pinning issues.

4. **Progressive enhancement** — The dashboard works as a static file (embedded JSON snapshot) or as a live SPA when served by `serve.py`. All new components follow this pattern.

5. **Confirmation modal pattern** — Pure CSS/JS modal with overlay, focus trapping, and ARIA attributes. Wired into `acceptOrder()`, `denyOrder()`, and `closePosition()` to prevent accidental destructive actions.

6. **Utility-first formatting** — All display formatting flows through shared JS functions (`formatCurrency`, `formatPctSigned`, `pnlState`, `isStale`, `classifyConfidence`, `classifyRisk`) to ensure consistency and reduce duplication.

7. **Computed PortfolioSummary** — A single `computePortfolioSummary(book, history, pending)` function derives all KPI values from raw state, keeping the computation centralized and testable.

8. **Sidebar narrowed (240px → 220px)** — Reclaims 20px for the main content area without sacrificing sidebar readability.

## 3. Assumptions

- **Initial capital is $10,000,000** — Used as the reference line in the equity chart and as the denominator for total P&L percentage calculations.
- **Maximum leverage is 3.0×** — Risk utilization is computed as `grossExposure / (3.0 × NAV)`.
- **Staleness threshold** — Data older than 24 hours on a weekday is considered stale; 4–24 hours is "aging."
- **`state.history`** — Expected to be an array of `{ date, nav, ... }` objects sorted chronologically.
- **`state.pending`** — Each item includes enriched sub-objects `_proposal`, `_techScore`, and `_risk` as provided by `serve.py`.
- **`state.debates`** — Filtered by `proposal_id` to show consensus for the most recent proposal(s).
- **Browser support** — Targets modern evergreen browsers (Chrome, Firefox, Safari, Edge). No IE11 support.
- **No persistent client state** — Sort order, filter text, and chart range selection reset on page reload; this is acceptable for MVP.
- **Color contrast** — The dark theme palette meets WCAG 4.5:1 for body text (`#e8e8e8` on `#101010`).
