# Requirements — Portfolio Dashboard Redesign

## Overview
Redesign the existing Agentic Trading Portfolio Overview dashboard into a professional, responsive, decision-oriented command center for a human-reviewed agentic trading system. The dashboard must immediately answer: Is the portfolio profitable? Is risk within limits? What actions require human review? What are agents recommending? Is the system healthy?

## Constraints
- Preserve the current dark visual identity and gold accent color scheme.
- Do not replace the project's framework (Python/Flask backend, vanilla JS frontend, inline CSS).
- Do not change backend API contracts unless necessary.
- Do not add external frontend frameworks (React, Vue, etc.) — this is a self-contained HTML dashboard generated by `dashboard.py` and served by `serve.py`.
- If data is unavailable, create typed mock adapters or graceful empty states rather than hard-coding misleading values.
- Do not execute real or paper trades without explicit API support and user confirmation.
- Use en-US currency formatting.

---

## Requirements

### 1 — Dashboard Header
**As a** portfolio operator,
**I want** a persistent dashboard header with title, subtitle, PAPER TRADING badge, last-updated timestamp, and action buttons (Run Agent Cycle, Refresh Data, Export Report),
**so that** I always know the system mode, data freshness, and can trigger key actions.

**Acceptance Criteria:**
- Title: "Portfolio Overview"
- Subtitle describes the portfolio (e.g., "Multi-Sector Hedged L/S | 11 Sectors | $10M NAV")
- PAPER TRADING badge is always visible, styled distinctly (amber/orange)
- Last-updated timestamp shows when data was last refreshed
- "Run Agent Cycle" button shows a confirmation modal before invoking any action
- "Refresh Data" triggers mark-to-market via `/api/mark`
- "Export Report" is a placeholder button (disabled until backend supports it)
- Buttons show loading states during async operations

---

### 2 — KPI Summary Cards
**As a** portfolio operator,
**I want** a responsive grid of KPI cards covering NAV, daily P&L, total P&L, cash, gross exposure, net exposure, drawdown, risk utilization, active positions, and pending recommendations,
**so that** I can assess portfolio health at a glance.

**Acceptance Criteria:**
- Each card includes: formatted value, contextual subtitle, optional trend indicator, loading state, unavailable-data state, accessible ARIA label
- Semantic colors: green (positive/approved), red (negative/breach), amber (warning/pending), blue (info/running), neutral gray (unavailable)
- Zero values render as neutral, not green
- Cards are responsive: 5-column on desktop, 3 on tablet, 2 on mobile
- Daily P&L shows both dollar and percentage
- Drawdown shows percentage from peak NAV
- Risk utilization shows gross leverage vs. max allowed (3.0x per spec)
- Pending recommendations count links to the Action Required panel

---

### 3 — Action Required Panel
**As a** portfolio operator,
**I want** a prominent panel showing recommendations awaiting my review with Approve/Reject/View Analysis actions,
**so that** I can make trade decisions without navigating away from the overview.

**Acceptance Criteria:**
- Panel appears directly below KPI section when pending orders exist
- Each recommendation shows: ticker, proposed action (LONG/SHORT), current price, target size (% NAV), confidence score, rationale summary, risk classification, timestamp
- Approve and Reject actions require a confirmation modal
- "View Analysis" expands or navigates to full proposal detail
- If no recommendations exist, show a polished empty state ("All caught up — no pending decisions")
- Panel has a distinct visual treatment (border accent, slightly elevated) to draw attention
- Badge count in sidebar/nav updates to match pending count

---

### 4 — Agent Consensus Component
**As a** portfolio operator,
**I want** a compact component showing how agents voted on the most recent proposal(s),
**so that** I can see agreement/disagreement at a glance without reading full debate transcripts.

**Acceptance Criteria:**
- Shows for each recent proposal: Fundamental Agent stance + confidence, Macro Agent stance + confidence, Technical score, Risk decision, PM recommendation
- Stances displayed as badges: SUPPORT (blue), CHALLENGE (red), DEFEND (gray), NEUTRAL (gray)
- Confidence shown as compact bars (1-10 scale)
- Disagreement warning when agents materially disagree (e.g., one challenges while others support)
- "View Full Debate" link navigates to the Debate tab
- Handles missing data gracefully (not all proposals have all agent responses)

---

### 5 — Equity and Risk Chart
**As a** portfolio operator,
**I want** an equity curve chart with time-range selectors, benchmark reference, tooltip, and optional drawdown view,
**so that** I can visualize portfolio performance over time.

**Acceptance Criteria:**
- Time-range selectors: 1D, 1W, 1M, 3M, ALL
- Portfolio equity series (from `pnl_history.json`)
- Initial-capital reference line ($10M horizontal)
- Tooltip with timestamp, NAV, return percentage
- Readable x-axis (date labels) and y-axis (dollar labels)
- Responsive resizing
- Loading state (skeleton)
- Error state
- Empty state for insufficient history (<2 data points): shows message, not a misleading line
- Do not stretch a single data point into a full-width line
- Uses inline SVG (existing approach) — no new charting library
- Optional drawdown toggle showing drawdown % from peak over time

---

### 6 — Position Summary Table
**As a** portfolio operator,
**I want** a sortable, filterable positions table with expandable row details,
**so that** I can review all positions with relevant context.

**Acceptance Criteria:**
- Columns: Ticker, Direction, Status, Entry Price, Current Price, Today P&L, Total P&L, Size (% NAV), Hedge, Confidence, Days Held, Actions
- Sortable by clicking column headers
- Search/filter by ticker
- Sticky header on scroll
- Responsive: horizontal scroll on mobile
- Loading skeleton state
- Empty state ("No active positions")
- Badges for direction (LONG green, SHORT red), status (ACTIVE green, CLOSED gray)
- Expandable row detail showing: investment thesis, agent votes, hedge details, entry rationale, exit criteria, risk triggers
- "Review Position" button (replaces direct "Close") opens a confirmation modal before any close action
- Tabular numeric alignment (right-align numbers)

---

### 7 — System Health Panel
**As a** portfolio operator,
**I want** a compact panel showing data freshness and system status,
**so that** I know if the system is operating normally.

**Acceptance Criteria:**
- Shows: last data refresh time, last agent cycle time, next scheduled cycle, stale-data warning (if last mark >24h old on a weekday)
- Status indicators for: market data (prices.db freshness), API connectivity (OpenRouter reachable), scheduler status (launchd agent loaded)
- Uses available data from `memos/logs/` (cycle timestamps) and `book.json` (last_marked field)
- When no endpoint exists for a status, show "Unknown" with gray indicator — not fake green
- Compact design: single row or small card, not a full panel

---

### 8 — Sidebar Improvements
**As a** portfolio operator,
**I want** the sidebar to clearly show navigation state, pending action count, and support responsive modes,
**so that** I can navigate efficiently on any device.

**Acceptance Criteria:**
- Active tab clearly highlighted (existing gold left-border + background)
- Pending orders badge count on the "Pending Orders" nav item
- Slightly narrower (220px from 240px) to give more content space
- Mobile: drawer mode (existing bottom nav) remains
- "Refresh Prices" button shows last refresh time and spinner during refresh
- Keyboard navigation (Tab/Enter) works for all nav items
- Collapsed desktop mode not required for MVP (keep full sidebar)

---

### 9 — Responsiveness and Accessibility
**As a** portfolio operator on any device,
**I want** the dashboard to be usable on desktop, tablet, and mobile with proper accessibility,
**so that** I can check the portfolio from my phone.

**Acceptance Criteria:**
- Desktop (>1024px): full sidebar + content
- Tablet (768-1024px): narrower sidebar or collapsed
- Mobile (<768px): bottom nav (existing), stacked cards, horizontal scroll tables
- Visible keyboard focus states on all interactive elements
- ARIA labels on metric cards, buttons, and status indicators
- Sufficient text contrast (4.5:1 minimum for body text)
- Buttons show disabled and loading states clearly
- No color-only communication (always pair color with text/icon)
- `prefers-reduced-motion` respected for animations

---

### 10 — Data Formatting and Types
**As a** developer,
**I want** consistent data formatting utilities and typed data models,
**so that** values are displayed consistently and the code is maintainable.

**Acceptance Criteria:**
- Currency formatting: `$10,000,000` (en-US, no decimals for large values, 2 decimals for per-share)
- Percentage formatting: `+1.65%` (always show sign for P&L)
- P&L semantic state function: returns "positive", "negative", or "neutral"
- Stale timestamp detection: returns true if >24h old on a weekday
- Confidence classification: "high" (8-10), "medium" (5-7), "low" (1-4)
- Risk classification: "approved", "warning", "breach"
- All formatting functions are JavaScript (inline in the generated HTML)
- No hard-coded portfolio figures in view logic — always read from state/API

---

### 11 — Confirmation Modals
**As a** portfolio operator,
**I want** all destructive or trade-affecting actions to require confirmation,
**so that** I never accidentally execute, approve, or close something.

**Acceptance Criteria:**
- Modal for: Accept trade, Deny trade, Close position, Run Agent Cycle
- Each modal shows: action description, affected ticker/position, cancel and confirm buttons
- Confirm button is styled distinctly (not same as cancel)
- Modal can be dismissed with Escape key or clicking outside
- Modal prevents background scroll
- No action executes without explicit confirm click

---

### 12 — Testing and Delivery
**As a** developer,
**I want** the implementation to be verified and documented,
**so that** it can be reviewed and merged confidently.

**Acceptance Criteria:**
- `dashboard.py` generates valid HTML (HTMLParser check passes)
- `serve.py` starts without import errors and all routes respond
- `mark_to_market.py` runs without errors
- `monitor.py` runs without errors
- All existing functionality (accept/deny/close/mark/chat) still works
- No new Python syntax errors in any modified file
- Summary of all changed files provided
- Architecture decisions documented
- Assumptions listed
- Backend endpoints or fields still needed listed
- Manual verification checklist provided
