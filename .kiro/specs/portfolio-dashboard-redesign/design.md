# Design — Portfolio Dashboard Redesign

## Architecture Overview

The dashboard is a **server-generated SPA** — `dashboard.py` produces a self-contained HTML file with embedded CSS, JavaScript, and fallback data. When served through `serve.py` (Flask), the JS fetches live data from REST endpoints. When opened as a static file (GitHub Pages), it displays embedded snapshot data.

### Current Stack
- **Backend**: Python 3.9+, Flask (serve.py)
- **Frontend**: Vanilla JavaScript (inline in HTML), no framework
- **Styling**: Inline CSS with CSS custom properties (`:root` variables)
- **Charting**: Inline SVG generated by JavaScript
- **State**: JSON files on disk (`memos/state/book.json`, `pnl_history.json`, `alerts.json`)
- **API**: REST endpoints in `serve.py` (`/api/book`, `/api/pending`, `/api/mark`, `/api/chat`, etc.)
- **Data Models**: Plain JSON objects (no TypeScript, no formal schema)

### Design Decisions
1. **No framework change** — stays vanilla JS. Complexity is managed through well-structured render functions.
2. **No new libraries** — SVG charts, CSS animations, no charting library added.
3. **Component model** — each UI section is a JavaScript `render*()` function that returns HTML strings. Not true components, but logically separated.
4. **Progressive enhancement** — works static (GitHub Pages) with embedded data; fully interactive when served by Flask.
5. **Confirmation modals** — pure CSS/JS modals, no library dependency.

## Data Flow

```
book.json ─────────┐
pnl_history.json ──┤
alerts.json ───────┤──→ dashboard.py ──→ index.html (embedded JSON snapshot)
proposals/*.json ──┤
debate/*.json ─────┤
orders/*.json ─────┤
scores/*.json ─────┤
risk/*.json ───────┤
logs/*.json ───────┘

serve.py ──→ /api/book        → live book state
         ──→ /api/pending     → pending orders (enriched with proposals/scores/risk)
         ──→ /api/mark        → trigger mark-to-market, return updated NAV
         ──→ /api/accept/<id> → execute trade into book
         ──→ /api/deny/<id>   → reject trade
         ──→ /api/close/<t>   → close position
         ──→ /api/history     → NAV snapshots for equity curve
         ──→ /api/chat        → LLM assistant
         ──→ /api/debates     → debate memos
         ──→ /api/risk        → risk assessments
         ──→ /api/scores      → technical scores
         ──→ /api/logs        → cycle logs
```

## Data Models (JavaScript)

```javascript
// Computed from state.book
PortfolioSummary = {
  nav, initialNav, totalPnlPct, totalPnlDollars,
  dailyPnlPct, dailyPnlDollars,
  cashPct, cashDollars,
  grossExposure, netExposure,
  drawdownPct, peakNav,
  riskUtilization, // gross leverage / 3.0 max
  activePositions, pendingCount
}

// Each position from state.book.positions
Position = {
  ticker, direction, hedgeTicker, hedgeDirection,
  entryPrice, currentPrice, entryDate, status,
  sizePctNav, conviction, stopLossMethod, takeProfit,
  unrealizedPnlPct, hedgeUnrealizedPnlPct, combinedPnlPct,
  dailyChangePct, priceHistory[], proposalId
}

// From state.pending (enriched)
TradeRecommendation = {
  orderId, proposalId, ticker, direction,
  hedgeTicker, hedgeDirection, sizePctNav,
  conviction, pmRationale, stopLossMethod, takeProfit,
  _proposal: { thesisSummary, variantPerception, catalyst, keyRisks },
  _techScore: { technicalScore, timingRecommendation },
  _risk: { decision, rationale }
}

// Derived from debates for a proposal
AgentVote = {
  agentId, stance, argument, round, revisedConviction
}

// From pnl_history.json
EquityPoint = { date, timestamp, nav, positions, cashPct, totalPnlPct }

// Computed from logs and timestamps
SystemHealth = {
  lastDataRefresh, lastAgentCycle, nextScheduledCycle,
  dataFreshness: "fresh" | "stale" | "unknown",
  alertCount, criticalAlerts
}
```

## Styling Strategy

### Color Palette (preserved + extended)
```css
--bg-primary: #101010;      /* page background */
--bg-secondary: #161616;    /* sidebar, headers */
--bg-card: #1c1c1c;         /* card backgrounds */

--text-primary: #e8e8e8;    /* headings, values */
--text-secondary: #a0a0a0;  /* body text */
--text-muted: #6b6b6b;      /* labels, captions */
--brand-gold: #c8a96e;      /* brand accent (sparingly) */
```

### New Additions
- `.badge-paper` — amber badge for PAPER TRADING indicator
- `.action-panel` — elevated card with left accent border for pending actions
- `.modal-overlay` — full-screen overlay for confirmation modals
- `.health-indicator` — small colored dot (green/amber/red/gray)
- `.sortable-header` — clickable column header with sort arrow

## Responsive Breakpoints
- **Desktop** (>1024px): Sidebar 220px + full content, 5-col KPI grid
- **Tablet** (768-1024px): Sidebar 180px, 3-col KPI grid, table scrolls
- **Mobile** (<768px): No sidebar (bottom nav), 2-col KPI grid, stacked cards, table horizontal scroll

---

## Accessibility

- All interactive elements reachable via Tab
- ARIA labels on: metric cards (`aria-label="NAV: $10,000,000"`), status badges, action buttons
- Focus visible styles (2px gold outline)
- Modal traps focus when open
- Color never sole indicator (always paired with text/icon)
- `prefers-reduced-motion`: disable fade-in animations
