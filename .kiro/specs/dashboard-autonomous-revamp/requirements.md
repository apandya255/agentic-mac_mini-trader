# Requirements Document

## Introduction

Revamp the Jimothy Capital dashboard to reflect the new autonomous trading mode. The dashboard must surface actionable insights from the Risk, IC Debate, and Technicals sections — replacing raw data dumps with synthesized analysis. The Book tab must display all new autonomous-mode fields (trim_status, trail_stop_level, thesis_status, sigma events) for existing positions. The overall goal is to make every tab immediately useful for monitoring a system that now auto-books trades, auto-trims profits, detects thesis breaks, and enforces circuit breakers without human intervention.

## Glossary

- **Dashboard**: The single-page HTML application served by serve.py at jimothy-capital.com, generated by dashboard.py
- **Book**: The collection of currently held positions and associated metadata stored in book.json
- **Position**: A long/short equity pair trade with entry data, P&L tracking, and autonomous lifecycle fields
- **Trim_Status**: State machine field on positions with values: "untrimmed", "half_trimmed", "fully_exited"
- **Trail_Stop_Level**: The trailing stop price level set after a 50% take-profit trim, calculated at 50% of unrealized gain from entry
- **Thesis_Status**: Field tracking whether a position's investment thesis remains valid; values: "active", "review_overdue"
- **Sigma_Event**: A detected outsized price move exceeding 2x the trailing 20-day standard deviation
- **Circuit_Breaker**: Safety mechanism that halts new bookings when intraday drawdown exceeds a threshold
- **Pipeline_Gates**: The three validation gates (conviction >= 5, risk approved, PM execute) that orders must pass for auto-booking
- **Overlap_Guard**: Mutual exclusion mechanism preventing concurrent pipeline cycle executions
- **IC_Debate**: Investment Committee debate records showing multi-agent argument exchanges per proposal
- **Risk_Assessment**: Per-proposal risk evaluation including factor betas, concentration checks, and hedge validation
- **Technical_Score**: Technical analysis scoring for tickers including momentum, trend, and volume signals
- **Alerts**: Monitoring outputs from monitor.py categorizing risk events by level (critical, warning, info)

## Requirements

### Requirement 1: Book Tab — Display Autonomous Position Lifecycle Fields

**User Story:** As a portfolio manager, I want to see trim status, trail stop level, thesis status, and sigma events for each position in the Book tab, so that I can monitor the autonomous lifecycle of every trade at a glance.

#### Acceptance Criteria

1. WHEN a position has a trim_status field, THE Dashboard SHALL display the trim_status value ("untrimmed", "half_trimmed", "fully_exited") as a color-coded badge in the position row
2. WHEN a position has a trail_stop_level set, THE Dashboard SHALL display the trail stop price and the percentage distance between current price and trail stop
3. WHEN a position has a thesis_status of "review_overdue", THE Dashboard SHALL highlight the position row with a warning indicator and display days overdue
4. WHEN a sigma_event has been detected for a position's ticker, THE Dashboard SHALL display a sigma event indicator with the magnitude and threshold that triggered it
5. THE Dashboard SHALL include trim_status, trail_stop_level, thesis_status, and sigma_event columns in the expandable detail panel for each position

### Requirement 2: Book Tab — Position Summary Metrics for Autonomous Mode

**User Story:** As a portfolio manager, I want a KPI strip on the Book tab summarizing autonomous mode activity, so that I can quickly assess the state of my portfolio's automated lifecycle.

#### Acceptance Criteria

1. THE Dashboard SHALL display a KPI strip on the Book tab showing: total active positions count, positions trimmed (half_trimmed count), positions with thesis overdue, and trail stop proximity (positions within 1% of trail stop)
2. WHEN the Book tab is rendered, THE Dashboard SHALL compute and display gross exposure, net exposure, and average pair P&L from active positions
3. WHEN any position has trim_status of "half_trimmed", THE Dashboard SHALL show the aggregated capital freed by trims as a metric

### Requirement 3: Risk Tab — Synthesized Risk Dashboard

**User Story:** As a portfolio manager, I want the Risk tab to show actionable, synthesized risk metrics instead of raw risk assessment data, so that I can quickly identify what needs attention.

#### Acceptance Criteria

1. THE Dashboard SHALL display an active alerts summary at the top of the Risk tab, grouped by severity level (critical, warning, info) with counts
2. WHEN alerts exist with level "critical", THE Dashboard SHALL render them prominently with red styling and recommended actions
3. THE Dashboard SHALL display a portfolio-level risk heatmap showing: drawdown from peak, gross leverage, net exposure, largest single-name concentration, and sector concentration violations
4. WHEN factor betas approach or breach the 0.6 limit, THE Dashboard SHALL display a factor exposure traffic-light grid (green/amber/red) with the numeric beta value
5. THE Dashboard SHALL display a correlation matrix or correlation alerts section showing positions with inter-position correlation exceeding 0.5
6. WHEN positions have price_history data, THE Dashboard SHALL compute and display trailing 20-day volatility for each position to contextualize sigma event thresholds

### Requirement 4: IC Debate Tab — Structured Decision Analysis

**User Story:** As a portfolio manager, I want the IC Debate tab to show a structured summary of each proposal's debate outcome, so that I can quickly understand why trades were approved or rejected without reading every argument.

#### Acceptance Criteria

1. WHEN debate records exist, THE Dashboard SHALL display a summary card per proposal showing: final conviction score, number of rounds, majority stance (support/challenge), and outcome (booked/rejected/pending)
2. THE Dashboard SHALL display a conviction distribution chart or visual showing how conviction evolved across debate rounds
3. WHEN a debate resulted in a booked trade, THE Dashboard SHALL link the debate card to the corresponding position in the Book tab
4. THE Dashboard SHALL allow expanding each debate card to reveal full argument history with agent identities, stances, and argument text
5. WHEN a debate has revised_conviction values, THE Dashboard SHALL display a conviction trajectory (initial → final) for each participating agent

### Requirement 5: Technicals Tab — Actionable Signal Summary

**User Story:** As a portfolio manager, I want the Technicals tab to present technical scores as actionable signals with context, so that I can see which positions are technically strong or deteriorating.

#### Acceptance Criteria

1. THE Dashboard SHALL display technical scores in a ranked table sorted by composite score, showing ticker, score, trend direction, and momentum classification
2. WHEN a position exists in the Book that also has a technical score, THE Dashboard SHALL annotate the score with the position's current P&L to show score-vs-performance alignment
3. WHEN a technical score drops below 40 for an active position, THE Dashboard SHALL flag it as "Weakening Technical" with a warning indicator
4. THE Dashboard SHALL group technical scores by sector and display sector-average scores for comparison

### Requirement 6: Autonomous Mode Status Panel

**User Story:** As a portfolio manager, I want a persistent autonomous mode status indicator showing system health, so that I can trust the system is operating correctly.

#### Acceptance Criteria

1. THE Dashboard SHALL display the circuit breaker state (active/inactive) with current intraday drawdown percentage in the top banner
2. WHEN the circuit breaker is active, THE Dashboard SHALL change the banner styling to indicate a halted state and display the drawdown level that triggered it
3. THE Dashboard SHALL display the timestamp of the last completed pipeline cycle in the top bar
4. WHEN an overlap_guard rejection has occurred in the most recent cycle, THE Dashboard SHALL display a "Cycle Skipped" indicator with timestamp
5. THE Dashboard SHALL display the total number of auto-booked trades (lifetime) and trades auto-booked in the current session

### Requirement 7: Run Log — Pipeline Execution Detail

**User Story:** As a portfolio manager, I want the Run Log tab to show detailed pipeline execution history with gate pass/fail per order, so that I can audit the autonomous booking decisions.

#### Acceptance Criteria

1. WHEN cycle logs exist, THE Dashboard SHALL display each pipeline cycle with: timestamp, number of proposals evaluated, orders that passed all gates, orders rejected with the failing gate identified
2. THE Dashboard SHALL display a per-order breakdown within each cycle showing: ticker, conviction score, risk decision, PM execute flag, and the gate result (passed/failed with gate name)
3. WHEN an order was held by the circuit breaker, THE Dashboard SHALL display the order with a "Circuit Breaker Held" status and the drawdown percentage at hold time
4. THE Dashboard SHALL display the most recent 20 cycles by default, with a "Load More" control to paginate through history

### Requirement 8: Overview Tab — Autonomous Trading Summary

**User Story:** As a portfolio manager, I want the Overview tab to provide a concise autonomous trading summary, so that I have a single-screen snapshot of portfolio health and system activity.

#### Acceptance Criteria

1. THE Dashboard SHALL display on the Overview tab: NAV, total P&L (dollar and percentage), gross and net exposure, cash percentage, active position count, and positions at risk (stop-proximity or thesis-overdue)
2. WHEN positions have been trimmed in the current session, THE Dashboard SHALL display "Trims Today" count and capital freed on the Overview tab
3. THE Dashboard SHALL display the equity curve chart with drawdown overlay, marking circuit breaker activation points on the timeline
4. WHEN alerts exist, THE Dashboard SHALL display an alert count badge in the Overview's risk summary section with the highest-severity alert message
