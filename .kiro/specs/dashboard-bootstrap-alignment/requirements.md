# Requirements Document

## Introduction

Align the portfolio dashboard (generated by `dashboard.py` as self-contained HTML) with the operational framework defined in the bootstrap specification files. The current dashboard shows simplified position and portfolio data; the aligned version displays positions in their canonical pair-ratio form, surfaces all risk metrics the specs mandate (factor betas, leverage regime, trail proximity, loss-at-trail), integrates the desk calendar, and renders pending orders in the full pitch format. All rendering uses inline vanilla JS + SVG with no external libraries, and degrades gracefully when data is unavailable.

## Glossary

- **Dashboard**: The self-contained HTML page generated by `dashboard.py` and optionally served by `serve.py`.
- **Pair_Ratio**: The level at which a paired position is quoted — `entry_price / hedge_entry_price` for the entry, `current_price / hedge_current_price` for current, and the high-water mark in the position's favor for peak.
- **Trail**: A trailing stop-loss expressed as a percentage (2–3%) from the position's peak ratio. Once the peak ratchets up, the trail follows and never loosens.
- **Loss_at_Trail**: The NAV impact if a position's trail is triggered, computed as `trail_pct × size_pct_nav × 10000` (in basis points of NAV).
- **Factor_Beta**: The book's net 12-month rolling beta to each of the 9 defined risk factors (DXY, SPX, 10Y, VIX, Growth/Value, Crude, Large/Small, HY Credit, Gold).
- **Leverage_Regime**: A categorical stance output by the Risk seat — one of LEAN-IN, NEUTRAL, or CUT — based on trailing P&L trend, average correlation, conviction distribution, and distance to the book drawdown gate.
- **Flip_Condition**: The stated thesis-invalidation trigger for a position, defined in the originating pitch and checked daily.
- **Conviction_Tier**: A position sized above 5% NAV (up to 8%), limited to 2 concurrent slots, requiring elevated gates (Technical ≥ 8/10, explicit Risk sign-off, PM memo).
- **Pitch_Format**: The standard telegram layout for pending recommendations as defined in AGENTS.md — thesis, counter-argument, entry/stop/target, size, technical score, risk verdict, factor deltas.
- **Desk_Calendar**: The `desk/calendar.md` file containing macro releases, CB decisions, earnings for book names, and market holidays for the current week.
- **Concentration_Limit**: Hard caps defined in AGENTS.md — max 4 positions and 15% NAV idea-leg notional per GICS sector and per country.

## Requirements

### Requirement 1: Position Display as Pair Ratios

**User Story:** As a portfolio manager, I want positions displayed as pair ratios (entry_price / hedge_entry_price), so that I see positions in the same level-based framework the book spec defines.

#### Acceptance Criteria

1. WHEN the Dashboard renders a position, THE Dashboard SHALL display the entry ratio computed as `entry_price / hedge_entry_price`, rounded to 4 decimal places.
2. WHEN the Dashboard renders a position, THE Dashboard SHALL display the current ratio computed as `current_price / hedge_current_price`, rounded to 4 decimal places.
3. WHEN the Dashboard renders a position, THE Dashboard SHALL display the peak ratio as the highest ratio reached in the position's favor since entry (long = highest, short = lowest), rounded to 4 decimal places.
4. WHEN the Dashboard renders a position, THE Dashboard SHALL derive and display the combined P&L as the percentage change from entry ratio to current ratio, not from individual leg prices.
5. WHEN position data does not include a peak ratio field, THE Dashboard SHALL default the peak ratio to the entry ratio and display it accordingly.

### Requirement 2: Trail and Target Proximity Indicators

**User Story:** As a portfolio manager, I want to see how close each position is to its trail trigger and target, so that I can anticipate exits before they happen.

#### Acceptance Criteria

1. WHEN the Dashboard renders a position, THE Dashboard SHALL display the trail percentage (2–3% band) as set by the Technical seat.
2. WHEN the Dashboard renders a position, THE Dashboard SHALL compute and display the distance from peak as `(peak_ratio - current_ratio) / peak_ratio × 100` as a percentage.
3. WHEN the Dashboard renders a position, THE Dashboard SHALL compute and display the distance to target as the percentage from current ratio to the +5% target level above the entry ratio.
4. WHEN a position's distance from peak is within 0.5 percentage points of the trail trigger percentage, THE Dashboard SHALL apply a red highlight to that position row.
5. WHEN a position's distance from peak is within 1.0 percentage points of the trail trigger percentage but more than 0.5 percentage points away, THE Dashboard SHALL apply an amber highlight to that position row.

### Requirement 3: Factor Beta Exposure Table

**User Story:** As a risk manager, I want a factor beta heatmap showing the book's net exposure to each of the 9 defined factors, so that I can identify factor drift before it breaches limits.

#### Acceptance Criteria

1. THE Dashboard SHALL display a factor exposure table containing exactly 9 rows: USD/DXY, SPX, Rates/10Y, VIX, Growth/Value, Crude/CL1, Large/Small, HY Credit, Gold/XAU.
2. WHEN factor beta data is available, THE Dashboard SHALL display the book's net beta value for each factor, rounded to 2 decimal places.
3. WHEN a factor's absolute beta exceeds 0.4, THE Dashboard SHALL highlight that factor cell in amber as an early-warning signal.
4. WHEN a factor's absolute beta exceeds 0.6, THE Dashboard SHALL highlight that factor cell in red as a breach signal.
5. THE Dashboard SHALL display the factor exposure table in the Risk tab.
6. THE Dashboard SHALL display a compact factor summary widget on the Overview tab showing any factors with absolute beta exceeding 0.4.
7. IF factor beta data is not yet computed or unavailable, THEN THE Dashboard SHALL display "—" in each factor cell with a "pending" label.

### Requirement 4: Leverage Regime Indicator

**User Story:** As a portfolio manager, I want the current leverage regime (LEAN-IN / NEUTRAL / CUT) displayed prominently, so that I immediately know the risk posture governing new positions.

#### Acceptance Criteria

1. THE Dashboard SHALL display the leverage regime as a badge on the Overview tab within the system health panel.
2. WHEN the leverage regime is LEAN-IN, THE Dashboard SHALL render the badge with a green background.
3. WHEN the leverage regime is NEUTRAL, THE Dashboard SHALL render the badge with a gray background.
4. WHEN the leverage regime is CUT, THE Dashboard SHALL render the badge with a red background.
5. IF leverage regime data is unavailable, THEN THE Dashboard SHALL display the badge as "—" with a neutral gray background.

### Requirement 5: Flip-Condition Per Position

**User Story:** As a portfolio manager, I want to see each position's thesis-invalidation condition on the dashboard, so that the daily coverage sweep has immediate visibility into what kills each trade.

#### Acceptance Criteria

1. WHEN a position detail row is expanded, THE Dashboard SHALL display a "Flip Condition" field containing the stated thesis-invalidation trigger from the originating pitch.
2. WHEN the originating pitch data includes a flip condition, THE Dashboard SHALL render it verbatim without truncation.
3. IF a position's flip condition data is unavailable, THEN THE Dashboard SHALL display "Not specified" in the Flip Condition field.

### Requirement 6: Pitch Format Compliance for Pending Orders

**User Story:** As a portfolio manager, I want pending recommendations displayed in the full pitch telegram format, so that I can evaluate proposals with all required information visible.

#### Acceptance Criteria

1. WHEN the Dashboard renders a pending order, THE Dashboard SHALL display the thesis in 3 lines or fewer, stating the variant view versus consensus.
2. WHEN the Dashboard renders a pending order, THE Dashboard SHALL display the best counter-argument in 1 line.
3. WHEN the Dashboard renders a pending order, THE Dashboard SHALL display entry, stop, and target levels with their numeric values.
4. WHEN the Dashboard renders a pending order, THE Dashboard SHALL display the size as percentage of NAV and the computed loss-at-trail in NAV basis points.
5. WHEN the Dashboard renders a pending order, THE Dashboard SHALL display the technical score as X/10 with key levels noted.
6. WHEN the Dashboard renders a pending order, THE Dashboard SHALL display the risk verdict (PASS, RESIZE, or REJECT).
7. WHEN the Dashboard renders a pending order, THE Dashboard SHALL display factor deltas for any factor exceeding absolute value 0.1.
8. IF any pitch field is missing from the order data, THEN THE Dashboard SHALL display "—" for that field rather than omitting the row.

### Requirement 7: Loss-at-Trail in NAV Basis Points

**User Story:** As a risk manager, I want each position's loss-at-trail displayed in NAV basis points, so that I can see the exact portfolio cost if any trail triggers.

#### Acceptance Criteria

1. WHEN the Dashboard renders a position, THE Dashboard SHALL compute and display loss-at-trail as `trail_pct × size_pct_nav × 10000` rounded to the nearest integer, labeled "bps".
2. THE Dashboard SHALL display a portfolio-level KPI showing the total loss-at-trail (sum across all positions) in NAV basis points on the Overview tab.
3. WHEN loss-at-trail data cannot be computed due to missing trail percentage, THE Dashboard SHALL display "—" for that position's loss-at-trail value.

### Requirement 8: Conviction Tier Tagging

**User Story:** As a portfolio manager, I want high-conviction positions (size > 5% NAV) visually distinct in the dashboard, so that I can immediately identify which positions use the elevated sizing tier.

#### Acceptance Criteria

1. WHEN a position's size_pct_nav exceeds 0.05 (5%), THE Dashboard SHALL render that position row with a gold border and a "HIGH CONVICTION" badge.
2. WHEN a position is tagged as high conviction, THE Dashboard SHALL display the "why this deserves size" memo from the originating order in the expanded detail view.
3. WHEN the Dashboard renders the position table, THE Dashboard SHALL display a conviction tier indicator column showing a distinct icon for positions exceeding 5% NAV.
4. IF the conviction memo is unavailable for a high-conviction position, THEN THE Dashboard SHALL display "Memo not available" in the expanded detail.

### Requirement 9: Desk Calendar Integration

**User Story:** As a portfolio manager, I want upcoming events from desk/calendar.md shown on the dashboard, so that I am aware of macro releases, CB decisions, and earnings that could affect open positions.

#### Acceptance Criteria

1. THE Dashboard SHALL display a compact calendar widget on the Overview tab showing upcoming events for the current week.
2. WHEN calendar data contains macro releases, THE Dashboard SHALL display each release with its date, time (ET), currency, release name, and consensus value.
3. WHEN calendar data contains CB decisions, THE Dashboard SHALL display each decision with its date, currency, and expected action.
4. WHEN calendar data contains earnings for book names, THE Dashboard SHALL display each earnings event with its date, ticker, and timing (BMO/AMC).
5. THE Dashboard SHALL provide a full Calendar section accessible via sidebar navigation showing all calendar categories.
6. IF desk/calendar.md is empty or contains only placeholder markers ("| — |"), THEN THE Dashboard SHALL display "No calendar data available" in the calendar widget.

### Requirement 10: Concentration Limits Display

**User Story:** As a risk manager, I want to see per-sector and per-country exposure versus the defined concentration limits, so that breaches or near-breaches are visible before a new pitch arrives.

#### Acceptance Criteria

1. THE Dashboard SHALL display a concentration table in the Risk tab showing each GICS sector that has at least one open position.
2. WHEN the Dashboard renders concentration data, THE Dashboard SHALL show the current position count versus the maximum of 4 per sector.
3. WHEN the Dashboard renders concentration data, THE Dashboard SHALL show the current aggregate idea-leg NAV percentage versus the maximum of 15% per sector.
4. WHEN a sector has 4 positions (at limit), THE Dashboard SHALL highlight that sector row in red.
5. WHEN a sector has 3 positions or aggregate NAV exceeds 12%, THE Dashboard SHALL highlight that sector row in amber as a near-limit warning.
6. IF country exposure data is available, THEN THE Dashboard SHALL display a separate country concentration table with the same limit logic (4 positions, 15% NAV per country).
7. IF country exposure data is unavailable, THEN THE Dashboard SHALL display "Country data pending" in the country concentration section.
